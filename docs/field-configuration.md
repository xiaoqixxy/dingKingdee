# 可选字段配置

流程：选择表单 → 选择明细表 → 字段配置（可选）→ 筛选排序 → 提交。

进入此步骤后，页面按所选单据元数据中的 `LookUpObjectFormId` 自动获取引用对象元数据并直接显示下拉。原默认值为 `FName` 的字段会默认选中 `FName`；已有特殊默认显示方式继续保留。不填写配置可直接“跳过，保持默认”，不改变原同步查询分支。相同连接与引用对象共用元数据请求，失败后允许重试。

默认字段列表只来自单据元数据，不再针对物料自动补加规格型号等关联属性列。引用对象属性仅在用户显式选择显示字段或新增输出行时加入取值配置。

## 配置格式

```json
{
  "fieldConfigs": [
    {
      "fieldId": "FInStockEntry_FMaterialId.FName",
      "alias": "规格型号",
      "referencePath": ["FSpecification"]
    }
  ]
}
```

- `fieldId` 为已有输出列标识，别名和显示值调整均不改列标识、记录主键。
- `alias` 只改变列名；空白恢复默认列名。
- `referencePath` 每段都是当前引用对象元数据中的字段 Key。选中另一个引用字段可继续向下配置，最多10级。最后一级留空则沿用该引用字段的默认显示方式。
- 例如物料的 `["FBaseUnitId", "FName"]` 表示从物料读取基本单位内码，再读取单位名称。
- 切换表单清空配置；切换明细范围移除不再存在的字段配置。配置随钉钉当前同步方案保存并恢复。

## 同一引用字段新增输出行

分组对象已接入项目内维护的扩展数据字典，可在子行选择名称、编码、内码、描述和父级分组属性；实际数据通过 QueryGroupInfo 获取。参见 [扩展数据字典](extension-data-dictionaries.md)。

引用下拉可直接输入名称或编码进行模糊搜索，支持方向键、回车选择和 Escape 取消。下拉浮层显示在滚动表格外，避免被子行或滚动区域裁切。

点击引用字段的“＋新增行”，可为同一个来源分别选择名称、编码、规格型号等取值，并分别设置别名。新增行可单独删除，原行继续保留。新增行配置增加 `outputFieldId`（创建时生成且保存后保持不变），`fieldId` 仍指向原来源字段。例如：

```json
{
  "fieldId": "FInStockEntry_FMaterialId.FName",
  "outputFieldId": "FInStockEntry_FMaterialId.FName__ref_example",
  "alias": "物料编号",
  "referencePath": ["FNumber"]
}
```

后端验证新增标识，复制原字段为独立输出列。新增表头列时同步调整明细边界，记录标识仍只使用原单据及明细主键。删除新增行后，移除其失效筛选、排序；返回上一流程再进入时保留仍存在的新增列条件。

## 接口与执行

`POST /api/referenceSchema`：请求体为 `{ "formId": "BD_MATERIAL", "params": "连接参数JSON" }`。只读调用当前连接的 `QueryBusinessInfo`，返回头/子头单值字段、引用对象标识及主键。

`/api/formSchema` 校验整份字段配置并返回最终字段名称、类型及枚举选项。`/api/sheetMeta` 与 `/api/records` 使用同一配置解析器，避免显示类型与实际取值不一致。内部取值计划不输出给钉钉字段接口。

不能假定金蝶支持任意多级点号路径。执行时先读取源引用内码，再按元数据主键分批查询各级引用对象；每批最多200个内码，同一请求缓存已查询值及不存在的内码。空引用显示为空，接口错误不会作为空引用吞掉。

没有按配置后的引用值筛选/排序时，保留原分页查询，仅补查当前页引用值。涉及配置后的引用值筛选或排序时，分批读取候选源记录并解析引用值，在筛选、排序、OR组去重之后分页。明细仍按单据分组；跨页表头填充、稳定记录标识及同步数量上限继续生效。这种情况可能扫描较多候选记录，耗时和内存随候选数量增长；优先增加单据日期等源字段条件缩小范围。

## 验证

- 前端测试覆盖跳过、别名恢复与提交、按层获取元数据、两级引用、恢复默认和重试。
- 后端测试覆盖路径白名单校验、类型转换、引用对象缓存、空引用、查询错误、筛选先于分页、排序和权益截断。
- 使用用户提供的连接对采购入库单做只读联调，物料规格型号以及物料→基本单位→名称均取值成功。报告仅记录校验状态，不保存凭证或业务值：`output/field-config-live-validation.json`。
