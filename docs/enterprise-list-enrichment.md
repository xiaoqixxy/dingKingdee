# 企业列表与企业名称关联

企业列表移除联系人、联系电话及联系人筛选；编辑表单仍保留联系人资料维护。新增企业套餐、上次使用时间、类型及类型筛选，不新增数据库持久化字段。

套餐通过企业 ID 关联 `ding_subscription` 和 `ding_product`。订阅表及企业表的企业 ID 均有唯一约束，避免连表造成分页重复。无订阅显示“未订阅”，存在订阅但产品缺失显示“套餐已移除”。

类型使用后端 `TenantType` 枚举，按以下顺序派生：

1. 无订阅：UNSUBSCRIBED（未订阅）。
2. 订阅状态已取消：CANCELLED（已取消）。
3. 订阅状态已过期：RENEWAL_DUE（待续费）。
4. 生效日期晚于当前时间：PENDING（待生效）。
5. 到期日期在未来 7 天内或已过期：RENEWAL_DUE（待续费）。
6. 当前订阅生效日期在近 7 天内：NEW（新订阅）。
7. 其余：ACTIVE（正常订阅）。

新订阅按当前订阅生效日期判断，不代表企业首次付费。免费套餐只要有订阅记录也按上述规则分类。企业启停状态仍为独立字段。

上次使用时间取以下时间的最大值（含失败调用）：钉钉 records 回调时间、同步执行开始时间、旧同步日志时间；金蝶元数据等接口不算同步使用。没有保留日志的企业显示“暂无使用记录”，不会拿创建时间冒充使用时间。

订单、订阅、发票、同步表单、金蝶连接配置、历史同步日志、执行记录、接口日志、业务审计、退款、支付日志、套餐变更记录和报表异常列表补充企业名称。保留企业 ID 便于区分同名企业，使用左连接保留没有企业档案的业务记录。通用日志在分页之后连表，计数条件保持不变。

验证：MySQL 只读验证 8 个列表查询；临时表验证 7 个分类场景、最新使用时间、无数据和类型筛选；自动化测试验证企业名称映射、企业 ID 查询、孤立记录保留及分页过滤。无需数据库迁移，部署新的后端 jar 与管理端资源后生效。
